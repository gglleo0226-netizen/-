# 친구들의 카드룸 v2.0.0

초대받은 친구 2~9명이 각자의 브라우저에서 즐기는 카드 게임입니다. **가상 칩 홀덤**과 **베팅 없는 카드 비교** 두 모드를 제공합니다. 가상 칩은 무료 게임 점수이며, 구매·환전·양도 거래·현금성 보상·결제 기능은 없습니다.

## 이번 버전에서 추가한 기능

- 홀덤의 폴드·체크·콜·베트/레이즈·올인, 서버 기준 차례 및 유효성 검사.
- 방 생성 시 초기 스택·SB·BB·행동 제한시간 설정. 기본 2,000 / 10 / 20 / 30초.
- 카드 섞기와 배분, D/SB/BB 이동, 2인 순서, 플롭·턴·리버 공개 및 족보 판정.
- 짧은 올인과 레이즈 재개 제한, 사이드 팟, 공동 승리, 미콜 초과 칩 반환.
- 폴드한 카드는 다른 참가자에게 결과나 기록에서도 공개하지 않습니다.
- 베팅 없는 카드 비교 모드에도 중간 폴드를 추가했습니다.
- 핸드 사이에 방장의 무료 전원 스택 재설정.

기존의 초대 링크, 방장 승인, 방 잠금, 자리 비움, 방장 양도, 재접속, 공개 결과 저장 기능을 유지했습니다.

## 현재 사용 중인 Render 서비스를 업데이트하는 방법

새 저장소나 새 Render 서비스를 만들 필요가 없습니다. **기존 파일과 같은 위치에 이번 파일들을 덮어쓰는 업데이트입니다.**

1. `friends_card_room_v2_update.zip`을 내려받아 압축을 풉니다. 압축 안에는 `package.json`, `server.mjs`, `lib/`, `public/`, `test/` 등이 바로 있습니다.
2. GitHub의 기존 저장소에서 `friends_card_room_no_betting` → `friends-card-room` 폴더로 들어갑니다. 이곳에 기존 `package.json`이 보여야 합니다.
3. 그 폴더에서 **Add file → Upload files**를 선택합니다. 압축 해제로 생긴 폴더의 **내용 전체**를 끌어넣습니다. ZIP이나 바깥 폴더 한 개를 올리는 것이 아닙니다.
4. 기존 파일과 같은 경로에 덮어쓸 내용이 올라갔는지 확인하고 `main` 브랜치에 커밋합니다. 브랜치 보호로 제안/PR을 만드는 경우에는 `main`으로 병합해야 합니다.
5. 현재 서비스는 커밋 시 자동 배포입니다. 새 배포가 시작되었으면 다시 수동 배포하지 않습니다. Render에서 Live 여부와 로그를 확인합니다.
6. 배포 후 기존 사이트를 새로고침하고 **새 방을 만듭니다.** 서버 재시작으로 기존 방은 사라집니다.

기존 서비스의 설정은 아래 그대로 유지합니다.

| 항목 | 값 |
|---|---|
| Root Directory | `friends_card_room_no_betting/friends-card-room` |
| Build Command | `npm ci && npm test` |
| Start Command | `npm start` |
| Runtime | Node |
| Instance / Plan | Free |

`no_betting`은 기존 폴더 이름일 뿐입니다. 그 안의 코드를 바꾸면 가상 칩 모드가 생깁니다. 폴더 이름을 바꾸거나 Root Directory를 다시 비우지 마세요. 기존 서비스 업데이트에는 동봉 `render.yaml`로 새 Blueprint를 만들 필요가 없습니다.

업데이트 확인: 홈페이지 제목에 v2, 방 만들기에 **가상 칩 홀덤 · 베팅 + 폴드**가 표시됩니다. 서비스 주소 뒤 `/healthz`를 열면 `"version":"2.0.0"`이 표시됩니다.

## 함께 플레이하는 순서

운영자는 게임 사이트에서 방 만들기 → 게임 방식 **가상 칩 홀덤 · 베팅 + 폴드** 선택 → 인원/스택/SB/BB/제한시간 설정 → 초대 링크 전달 → 요청 승인 순으로 진행합니다. 참가자는 초대 링크 열기 → 닉네임 → 승인 후 준비하기만 하면 됩니다. 모두 준비하면 방장이 카드 나누기를 누릅니다. 방장도 일반 참가자와 마찬가지로 자기 카드만 받습니다.

카드 배분과 정산은 자동이며, 사람은 자기 차례에 행동만 선택합니다. 다음 핸드 자동 시작을 켜도 가상 칩 모드에서는 다음 핸드 참가자 전원이 준비해야 시작합니다.

### 폴드

가상 칩 모드에서는 **내 차례**에 폴드할 수 있습니다. 이번 핸드에서 승리할 자격을 포기하며 이미 낸 칩은 팟에 남습니다. 폴드한 카드는 다른 사람에게 공개되지 않고, 본인만 계속 볼 수 있습니다. 폴드는 되돌릴 수 없습니다. 다음 핸드에 스택이 남아 있으면 다시 준비해 참가할 수 있습니다. 이미 올인한 뒤에는 폴드할 수 없습니다.

카드 비교 모드는 베팅 차례가 없으므로 진행 단계 중 언제든 폴드할 수 있습니다. 남은 사람이 한 명이면 미공개 카드를 열지 않고 그 사람이 승리합니다.

### 칩과 레이즈

레이즈 입력은 **현재 베팅 단계의 총액**입니다. 이미 20칩을 냈고 총액을 60으로 입력하면 추가로 40칩을 냅니다. 화면에 추가 금액과 남는 스택이 표시됩니다. 이번 핸드 전체의 누적 투입액과는 다릅니다.

최소 레이즈에 못 미치는 증액은 올인일 때만 허용합니다. 짧은 올인만으로 이미 행동한 사람의 레이즈 권한이 무조건 다시 열리지 않습니다. 누적 증액이 마지막 정상 레이즈 크기에 도달했는지도 검사합니다.

올인 금액이 다르면 메인/사이드 팟별 승리 자격을 분리합니다. 동률은 팟을 나누고, 나누어떨어지지 않는 칩은 D 다음 자리부터 해당 승자에게 배정합니다. 콜되지 않은 초과분은 반환합니다. 모든 상대가 폴드하면 승자 개인 카드와 아직 공개하지 않은 공통 카드를 숨긴 채 정산합니다.

상대가 모두 올인이 되어 더 이상 베팅할 수 없으면 남은 콜/폴드 결정만 받은 뒤 공통 카드와 결과를 바로 공개합니다. 올인 런아웃 애니메이션이나 공개 간격은 별도로 없습니다.

### 설정·재설정·자리 비움

설정은 핸드 사이에 변경합니다. SB/BB와 제한시간은 다음 핸드부터 적용됩니다. 초기 스택 값을 수정하는 것만으로 현재 스택을 덮어쓰지는 않습니다. 모든 사람을 같은 스택으로 다시 시작하려면 핸드가 끝난 후 방장 관리의 **전원 스택 무료 재설정**을 누릅니다. 기록은 남고 준비 상태는 초기화됩니다.

시간 초과 시 추가 칩 없이 가능하면 체크, 아니면 폴드하며 다음 핸드는 자리 비움으로 처리합니다. 일시정지는 행동 타이머와 진행을 멈춥니다. 명시적으로 방에서 나가면 진행 중 비올인 카드는 폴드 처리하고, 이미 올인한 카드는 결과까지 유지합니다.

D는 참가 가능한 다음 사람으로 이동하는 친구용 이동 버튼 방식입니다. 2인일 때는 D=SB이고 프리플롭 선행, 이후 후행입니다. 탈락자가 있는 정식 대회의 데드 버튼 전체 규칙을 구현한 것은 아닙니다.

## 로컬 실행

Node.js 22 또는 24를 설치한 뒤 이 폴더에서:

```sh
npm ci
npm test
npm start
```

브라우저에서 `http://localhost:3000`을 엽니다. Windows는 `START_WINDOWS.bat`을 실행할 수 있습니다. 외부 npm 패키지 의존성은 없습니다. 여러 사람을 시험하려면 서로 다른 브라우저 프로필/시크릿 창/기기를 사용합니다. 같은 프로필의 일반 탭은 같은 자리를 공유합니다.

선택 환경변수:

| 이름 | 용도 |
|---|---|
| PORT | 서버 포트. 기본 3000. Render가 제공하는 값 사용. |
| CREATE_ROOM_PASSWORD | 방 생성 비밀번호. 생략하면 사이트 방문자가 방을 만들 수 있음. 방 입장은 별도의 초대와 승인 필요. |

운영자 비밀번호나 API 키를 코드에 넣거나 저장소에 올리지 마세요.

## 구현 및 보안 범위

Node 내장 HTTP 서버 + 인증된 롱폴링 동기화입니다. Socket.IO/WebSocket 의존성은 없습니다. 카드와 상태의 기준은 서버이며, 클라이언트가 임의로 카드·스택·결과를 결정할 수 없습니다. 참가 토큰은 서버에서 해시로 보관하고, 요청 식별자·핸드·단계·차례 식별자를 검사해 중복 또는 늦은 베팅을 거절합니다. 입장 승인 전에는 플레이어 목록, 카드, 칩을 받지 않습니다.

서버에서 `crypto.randomInt`로 덱을 섞고, 상대 카드와 미공개 보드는 클라이언트로 전송하지 않습니다. 다만 서버 운영자가 서버 코드를 바꿀 수 있는 구조이므로 운영자에게도 검증 가능한 분산 셔플이나 상용 게임 수준의 부정행위 방지 인증을 제공하는 것은 아닙니다. 단말 자체 침해, 인증 토큰 공유, 참가자끼리 별도 연락하는 담합은 막을 수 없습니다.

## 저장과 운영 한계 — 중요

상태는 **서버 메모리에만 저장**합니다. 서버 재시작, 재배포, 프로세스 종료 시 방/카드/스택/기록이 사라집니다. 재접속은 같은 서버에 방이 살아 있을 때만 가능합니다. 공개 결과 저장은 결과 열람용이며 게임 복원 파일이 아닙니다.

현재 구현은 Node 프로세스/인스턴스 하나를 전제로 합니다. 여러 인스턴스 수평 확장이나 데이터베이스 복원 기능이 없습니다. 인터넷 중단이나 호스팅 중단이 발생할 수 있고 영구 보존을 보장하지 않습니다. 친구용 게임으로 사용하고 칩에 금전적 가치를 붙이지 마세요.

## 테스트

`npm test`: 자동 테스트 97개 통과. 그중 무작위 1,000핸드 검사는 종료·정수/비음수 스택·칩 보존을 확인합니다. 별도로 `npm run test:exhaustive`를 실행해 5장 조합 2,598,960개를 검사했습니다. 이것은 모든 홀덤 진행 상황의 완전한 검증은 아닙니다.

브라우저 화면 검사는 로컬 Chromium + 테스트용 API 연결로 폴드/콜/레이즈/결과/설정/재설정을 확인했습니다. 실제 Render에서 여러 외부 기기가 접속하는 검사는 아직 하지 않았습니다. 배포 후 2명으로 한 핸드를 시험하세요. 상세는 `TEST_REPORT.md`를 참고하세요.
