# 검증 기록

검증 대상: friends-card-room 1.0.0 / 작성일 2026-10-06

## 실행한 검증

- Node v22.16.0에서 `npm test`: **53개 테스트 통과**.
- `npm run test:exhaustive`: 서로 다른 5장으로 이루어진 **2,598,960개 모든 조합**을 열거하고
  9가지 분류의 개수를 비교해 통과. 이 검사는 7장 전체 133,784,560개를 전수 검사한 것이 아님.
- A–2–3–4–5, 로열 플러시, 복수 트리플/페어에서의 최선 선택, 키커, 공동 승리 등 개별 테스트.
- 2~9인 카드 중복 검사, 사용자별 비공개 카드 응답 분리, 9개의 HTTP 클라이언트 동시 진행.
- 승인 전 정보 제한, 방장 권한, 부정확한 초대 링크, 방 잠금, 링크 변경, 정원 검증.
- 중복 요청 ID, 이전 단계 요청 거부, 재접속용 인증 재사용, 일시정지·재개.
- 시간 공개, 자동 다음 라운드, 연결 끊김, 방장 인계, 퇴장·대기자·만료 정리.
- HTTP 인증, 출처 확인, JSON 형식, 정적 파일 범위, 보안 응답 헤더, long polling 동작.

## 브라우저 UI 확인

테스트 환경의 관리형 Chromium은 URL 탐색이 비활성화되어 있어, 실제 서버 주소로 직접
이동하는 방식 대신 다음 테스트 하니스를 사용했다.

1. 실제 HTML/CSS/JavaScript를 Chromium 페이지에 로드했다.
2. 테스트용 주소와 저장소를 주입하고, 브라우저의 API 요청을 로컬 Node HTTP 서버로
   전달했다. 게임 응답은 모의 데이터가 아닌 실제 서버에서 생성한 상태이다.
3. 데스크톱/모바일 크기의 서로 다른 화면에서 생성, 초대, 승인 대기, 입장, 준비,
   확인, 일시정지·재개, 결과 표시, 방장 설정 변경을 시험했다.
4. 별도 HTTP 참가자를 더해 9인 결과와 각 참가자의 최선 5장이 표시되는지 확인했다.
5. 접속 인증을 보관한 새 테스트 페이지에서 같은 자리·같은 라운드에 복귀하는지 확인했다.
6. 1440px 데스크톱, 390px 모바일 게임 화면, 360px 모바일 시작 화면의 가로 넘침을 확인했다.

UI 하니스 검사 8개가 통과했고, 실행 도중 앱 JavaScript의 pageerror는 없었다.
모바일 사이드 패널 너비를 수정한 후 재검사했다.

## 아직 실행하지 않은 검증

- 실제 Render 계정에 이 프로젝트를 배포하는 작업.
- 외부 인터넷과 실제 여러 기기의 브라우저 사이 네트워크 통신.
- 실제 Safari/iOS, Android 기기의 장시간 백그라운드·복귀 동작.
- 브라우저의 원래 localStorage와 실제 페이지 새로고침까지 포함하는 네이티브 브라우저 E2E.
- 부하 시험, 정식 보안 감사, 장시간 운영, 서버 재시작 후 게임 복원.

서버 재시작 후 복원은 이 버전에 포함되어 있지 않다. 배포 후 README의 2인 확인 절차를
먼저 실행해야 한다. 통과한 테스트가 모든 오류의 부재나 실제 서비스 운영을 보증하는 것은 아니다.
