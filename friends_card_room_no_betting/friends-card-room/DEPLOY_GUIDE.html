FRIENDS CARD ROOM · SETUP GUIDE

설치부터 친구 초대까지.

베팅 없는 2~9인 카드 비교 게임의 운영자용 설명서입니다. 최초 배포는 운영자만 하고, 참가자는 초대 링크로 들어옵니다.

설명서 목차1. 들어 있는 기능2. 최초 배포: 운영자만 진행3. 게임할 때마다 운영자가 할 일4. 친구들에게 안내할 내용5. 진행 방식과 예외 상황6. 꼭 알아둘 저장·운영 한계7. 혼자 배포 전 실행하기 — 선택 사항8. 배포 후 직접 해 볼 확인 절차9. 자주 만나는 문제10. 기술 구성과 검증 자료
처음에는 2~4번부터 읽으세요.
코드 업로드 → Render 배포 → 방 만들기 → 초대·승인 순서입니다. 이 파일은 설명서이며 게임 접속 페이지가 아닙니다.

친구들의 카드룸

2~9명이 각자의 브라우저에서 함께 사용하는 베팅 없는 온라인 카드 비교 게임입니다. 개인 카드 2장과 공통 카드 5장 중 가장 강한 5장을 비교합니다. 베팅, 칩, 블라인드, 거래 가능한 포인트, 현금, 상품, 결제 기능은 없습니다.

이 묶음은 실행 가능한 웹앱 소스 코드입니다. 배포된 사이트 주소가 아닙니다. public/index.html을 더블클릭하는 방식으로 온라인 게임을 실행할 수는 없습니다. 아래 순서대로 서버를 실행하거나 Render에 배포해야 합니다.

1. 들어 있는 기능

  • 방 정원 2~9명, 방 이름·닉네임 설정.
  • 초대 링크와 방장 승인. 방 잠금, 초대 링크 갱신, 요청 거절, 라운드 사이 참가자 퇴장.
  • 서버에서 덱을 섞고 각자의 카드 배분. 결과 공개 전 다른 사람의 개인 카드와 아직 공개하지 않은 공통 카드, 남은 덱을 클라이언트로 보내지 않음.
  • 개인 카드 → 플롭(3장) → 턴(4장) → 리버(5장) → 결과.
  • 전원 확인 방식 / 시간 공개 방식(5·10·15·30·60초). 시간 모드도 모두 확인하면 일찍 넘어감.
  • 가장 강한 5장 표시, 단독승·공동승 판정, 참여·승리 횟수 기록. 무늬로 동률을 깨지 않음.
  • 첫 D 위치 무작위 배정, 다음 라운드부터 참가 중인 다음 자리로 D 이동.
  • 다음 라운드 자동 시작 선택. 확인 모드는 전원 준비 시, 시간 모드는 결과 표시 12초 후.
  • 일시정지·재개, 다음 단계 바로 공개, 다음 라운드 쉬기, 방장 넘기기.
  • 브라우저 접속 인증을 이용한 재접속, 35초 응답 없는 참가자 자동 확인, 방장 연결이 90초 이상 끊겼을 때 다른 참가자가 방장 인계.
  • 최근 30라운드 공개 결과 보기와 JSON 저장. 이 JSON은 기록 보관용이지 복원용이 아님.
  • PC·휴대폰 화면 대응. 별도 앱 설치나 참가자 계정 가입 없이 브라우저로 이용.

베팅 결정을 하는 일반 홀덤과는 다릅니다. 참가자는 카드 확인과 다음 라운드 준비를 선택하고, 카드 공개와 조합 비교를 즐기는 게임입니다.

2. 최초 배포: 운영자만 진행

Render 가입과 ChatGPT 접근 허용까지 했다면, 가입을 다시 할 필요는 없습니다. 다만 ChatGPT↔Render 연결과 Render↔GitHub 저장소 연결은 서로 다른 작업입니다. 이 코드를 올려 둘 GitHub 저장소를 만든 뒤 Render에서 그 저장소에 접근하도록 승인하세요.

2-1. ZIP 압축 해제와 GitHub 업로드

  1. GitHub 계정을 준비하고 새 저장소를 만듭니다. 이름 예: friends-card-room. 공개 또는 비공개 모두 가능하며, 개인 운영이라면 비공개로 두어도 됩니다.
  2. 빈 저장소 화면의 uploading an existing file, 또는 Add file → Upload files를 엽니다.
  3. ZIP을 압축 해제한 friends-card-room 폴더 안의 내용 전체를 올립니다. ZIP 파일 자체만 올리거나, 상위 폴더를 한 겹 더 넣지 마세요.
  4. 변경 사항을 커밋합니다. 기본 브랜치 이름을 확인합니다. 보통 main입니다.

.node-version과 .gitignore도 포함되어 있습니다. 숨김 파일이 업로드에서 빠졌더라도 아래 Render 환경변수 NODE_VERSION=22를 설정하면 버전을 지정할 수 있습니다. test/ 폴더는 배포 중 자동 테스트를 실행하므로 꼭 함께 올려 주세요.

2-2. Render 웹 서비스 생성

Render에서 New → Web Service를 선택합니다. Static Site가 아닙니다. GitHub를 연결하고 위 저장소를 선택합니다. 비공개 저장소라면 해당 저장소에 대한 접근 권한을 Render에 허용해야 목록에 나타납니다.

항목 입력값
Name 구분할 수 있는 이름. 예: friends-card-room
Language / Runtime Node
Region Singapore 선택 가능
Branch 실제 업로드한 브랜치. 보통 main
Root Directory 비워 둠. 저장소 최상위에 package.json이 있어야 함
Build Command npm ci && npm test
Start Command npm start
Instance / Plan Free
Environment Variable NODE_VERSION = 22
Health Check Path /healthz

Create Web Service로 배포합니다. 이 앱은 데이터베이스, 유료 디스크, 유료 부가 서비스 없이 웹 서비스 한 개로 실행하도록 만들었습니다. 선택된 요금제가 Free인지 화면에서 직접 확인하세요. 기존 계정의 다른 리소스 요금까지 이 코드가 관리하거나 차단하는 것은 아닙니다.

배포가 완료되면 Render가 실제 접속 주소를 표시합니다. 그 주소가 게임 사이트입니다. 배포되지 않은 예시 주소나 로컬 주소를 친구에게 보내지 마세요.

자동 배포는 꺼 두는 편이 좋습니다. 게임 중 GitHub를 수정했을 때 서버가 재시작되어 방이 초기화되는 일을 피하기 위해서입니다. 업데이트는 게임이 끝난 뒤 Render에서 수동 배포하세요.

2-3. 다른 방법: render.yaml로 설정 읽기

수동 입력 대신 Render의 Blueprint 생성에서 이 저장소를 선택해 render.yaml을 읽도록 할 수도 있습니다. 이 파일은 웹 서비스 하나, Node 22, Singapore, Free, npm ci && npm test, npm start, /healthz, 자동 배포 끄기를 지정합니다. 2-2의 웹 서비스 생성과 둘 다 실행하면 서버가 두 개 생길 수 있으니 한 방법만 사용하세요.

선택 사항: 아무나 새 방을 생성하지 못하게 하려면 Render 환경변수에 CREATE_ROOM_PASSWORD를 추가하세요. 새로 정한 비밀번호를 넣으면 방 생성 화면에서만 그 비밀번호를 요구합니다. 친구들은 기존 방의 초대 링크와 승인만 있으면 됩니다. Render·GitHub 계정의 로그인 비밀번호를 이 값으로 재사용하지 마세요. 환경변수 변경으로 재배포되면 기존 방은 초기화됩니다.

3. 게임할 때마다 운영자가 할 일

  1. 배포된 게임 주소에 접속합니다.
  2. 닉네임, 방 이름, 최대 인원, 진행 방식을 정하고 방 만들기를 누릅니다.
  3. 방 안의 초대 링크 복사를 눌러 친구들에게 보냅니다. 홈페이지 주소만 보내는 것과 다릅니다. 초대 링크에는 방 코드와 입장 인증이 있습니다.
  4. 입장 요청에서 닉네임을 확인하고 승인합니다.
  5. 참가자가 모두 모이면 추가 입장 잠그기로 신규 입장을 막을 수 있습니다.
  6. 방장 자신을 포함한 참가자 모두 준비하기를 누릅니다.
  7. 방장의 카드 나누기가 활성화되면 누릅니다.

이후 카드 섞기, 배분, 공통 카드 공개, D 이동, 조합 비교, 동률 판정과 기록은 서버에서 처리합니다. 방장이 카드를 나누거나 승자를 직접 입력할 필요는 없습니다. 방장도 결과 공개 전에는 자기 카드만 받습니다.

4. 친구들에게 안내할 내용

그대로 보내도 되는 문장:

이 초대 링크를 Chrome·Edge·Safari 같은 브라우저에서 열고, 내가 알아볼 수 있는 닉네임으로 입장을 요청해 줘. 내가 승인하면 ‘준비하기’를 눌러 줘. 시작 후 자기 카드를 보고 ‘확인했어요’를 누르면 돼. 돈이나 칩을 거는 기능은 없어. Render나 GitHub 가입, 앱 설치는 필요 없어. 화면을 오래 끄면 연결 끊김으로 처리될 수 있어.

서로 다른 인터넷 연결에서도 배포된 같은 서버 주소를 이용합니다. 한 브라우저의 같은 사용자 프로필에서는 한 자리로 복귀합니다. 같은 PC에서 혼자 두 명을 시험하려면 Chrome 일반 창 + Edge처럼 브라우저를 분리하거나 일반 창과 별도 시크릿 세션을 사용하세요. 일반 탭 두 개만 열면 같은 자리입니다. 시크릿 세션을 모두 닫거나 브라우저 저장 데이터를 지우면 접속 인증도 사라질 수 있습니다.

5. 진행 방식과 예외 상황

모두 확인하면 공개

이번 라운드에 참가 중인 사람들이 ‘확인했어요’를 누르면 다음 단계가 공개됩니다. 결과 다음에는 각자 준비하고 방장이 다음 라운드를 시작합니다. ‘다음 라운드 자동 시작’을 켜면 접속 중인 참가자 전원이 준비했을 때 바로 시작합니다.

시간이 지나면 공개

설정한 시간이 지나면 서버가 다음 단계로 넘어갑니다. 전원이 먼저 확인하면 일찍 넘어갑니다. 다음 라운드 자동 시작을 켜면 결과를 12초 보여 준 뒤, 접속 중이며 자리 비움이 아닌 참가자들을 대상으로 다음 라운드를 시작합니다. 2명 미만이면 자동 시작을 멈추고 기다립니다.

잠시 연결이 끊겼을 때

같은 브라우저에 접속 인증이 남아 있고, 같은 서버 프로세스에서 방이 살아 있으면 재접속해 자기 자리로 돌아올 수 있습니다. 닉네임만 입력해서 기존 자리를 가져오지는 못합니다. 서버가 35초 동안 참가자의 요청을 받지 못하면 연결 끊김으로 보고 공개 진행에서 자동 확인합니다. 모두 끊겼을 때는 카드 공개를 계속 진행하지 않습니다. 휴대폰이 브라우저를 백그라운드로 보내면 이런 처리가 발생할 수 있습니다.

방장이 직접 나가면 남은 참가자에게 방장이 넘어갑니다. 연결만 끊겼을 때는 90초가 지난 후 남은 참가자 화면에 방장 인계 버튼이 나타납니다. 전원 퇴장 또는 마지막 승인 참가자의 퇴장으로 방이 종료되면 다시 만들어야 합니다.

라운드 도중 ‘다음 라운드 쉬기’를 누르면 이번 카드는 유지하고 다음 라운드부터 빠집니다. 라운드 도중 새로 승인된 사람은 공통 카드를 보며 기다리고, 다음 라운드부터 카드를 받습니다. 이번 라운드에 참가한 사람이 도중에 나가도 이미 나눈 카드는 이번 결과 비교에 남습니다. 퇴장 버튼에 대한 설명을 확인한 뒤 사용하세요.

6. 꼭 알아둘 저장·운영 한계

이 버전의 방, 카드, 기록, 접속 인증은 서버 메모리에만 있습니다. 외부 데이터베이스나 영구 저장을 구현한 버전은 아닙니다.

  • 서버 재시작, 재배포, 무료 서버 절전 후 재기동 시 기존 방과 진행 기록이 사라집니다.
  • 로컬 브라우저 저장은 자기 자리의 인증을 보관할 뿐, 서버의 게임 상태를 복구하지 않습니다.
  • 공개 결과 JSON은 보관용이며 새 방에 불러와 게임을 이어 하는 기능은 없습니다.
  • 서버는 인스턴스 한 개로 운영하세요. 여러 인스턴스가 방 정보를 공유하지 않습니다.
  • 모든 사용자가 6시간 넘게 응답하지 않는 방은 정리합니다. 대기자도 장기간 끊기면 만료됩니다.
  • 일반 웹 사이트처럼 서버 운영자는 코드와 서버 메모리에 접근할 수 있습니다. 서버 운영자에게도 덱이 암호학적으로 숨겨지는 구조나 전문 부정행위 방지 시스템은 아닙니다.
  • 링크와 닉네임 승인만으로 실제 신원을 인증하지는 않습니다. 신뢰하는 친구끼리 이용하고, 초대가 유출되면 링크 갱신·방 잠금·참가자 관리를 사용하세요.

Render 공식 무료 서비스 문서(2026-10-06 확인)에 따르면 무료 웹 서비스는 15분간 들어오는 트래픽이 없을 때 절전으로 전환되고, 다음 접속 때 다시 시작하는 데 시간이 걸릴 수 있습니다. 무료 리소스에도 월간 이용량 제한이 있습니다. 이 앱은 별도 유료 리소스를 만들지 않지만, 가입한 플랫폼의 표시 요금과 사용량 제한은 직접 확인하세요.

7. 혼자 배포 전 실행하기 — 선택 사항

Node.js 22 또는 24가 설치되어 있어야 합니다. 참가자에게는 Node.js가 필요하지 않습니다. 폴더에서 터미널을 열어 실행합니다.

npm ci
npm test
npm start

브라우저에서 http://localhost:3000을 엽니다. Windows에서는 START_WINDOWS.bat을 실행하고 안내된 로컬 주소를 열어도 됩니다. 로컬 서버 창을 닫으면 게임도 종료됩니다. localhost는 해당 기기 자신을 가리키므로 인터넷 친구들에게 보내는 공유 주소가 아닙니다. 실제 공유는 Render 배포 후 하세요.

전수 판정 검사를 추가 실행하려면 다음 명령을 사용합니다.

npm run test:exhaustive

외부 npm 의존 패키지가 없으며, Node 표준 모듈과 브라우저 기능만 사용합니다. 플랫폼에 npm과 Node가 제공되면 별도의 게임 라이브러리 설치는 필요하지 않습니다.

8. 배포 후 직접 해 볼 확인 절차

처음에는 친구 한 명과 2인 방으로 확인하세요.

  1. 두 기기에서 링크 접속, 입장 승인, 준비, 카드 나누기가 되는지 확인합니다.
  2. 자기 카드 2장은 보이고 상대 카드가 뒷면으로 표시되는지 확인합니다.
  3. 모두 확인 → 플롭 3장 → 턴 4장 → 리버 5장 → 결과가 같은 순서로 나타나는지 확인합니다.
  4. 결과에 참가자 이름, 조합 이름, 가장 강한 5장이 나오는지 확인합니다.
  5. 한 기기만 새로고침해 같은 자리로 돌아오는지 확인합니다.
  6. 다음 라운드에서 D가 이동하는지, 시간 공개 옵션과 방장 일시정지가 동작하는지 확인합니다.

시험 결과와 검증 범위는 TEST_REPORT.md에 적었습니다. 실제 Render 배포, 실제 휴대폰 Safari 환경에서의 네트워크 통신은 이 패키지를 생성할 때 실행한 테스트가 아니므로 위 절차로 직접 확인해야 합니다.

모바일에서 확인이 저절로 처리됨 앱 전환·화면 잠금으로 35초 이상 응답이 끊겼는지

10. 기술 구성과 검증 자료

  • server.mjs: 정적 화면 제공, JSON API, 인증된 long polling, 출처 확인, 요청 크기·빈도 제한.
  • lib/game.mjs: 서버 권한 기반 방·참가·라운드 관리, 사용자별로 분리된 상태 응답.
  • lib/cards.mjs: 암호학적 난수를 이용한 Fisher–Yates 셔플, 7장 중 최선의 5장 비교.
  • public/: 프레임워크 없는 한국어 반응형 화면.
  • test/: Node 기본 테스트 러너로 실행하는 규칙·권한·HTTP·동시성 테스트.

API는 준비/확인 요청에 라운드 ID와 단계 정보를 검사해, 화면이 넘어간 뒤 도착한 이전 버튼 입력이 새 단계의 확인으로 처리되지 않게 합니다. 요청 ID로 중복 처리도 막습니다. 초대 인증은 URL의 fragment에 두고, 참가자 인증은 HTTP Authorization 헤더로 전송합니다. 사용자 문자열은 화면에서 이스케이프하며, 서버는 공개 폴더의 정해진 파일만 제공합니다.
