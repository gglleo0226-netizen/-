1. 이번 ZIP의 압축을 풉니다

friends_card_room_v2_update.zip을 내려받아 압축을 풉니다. 이 ZIP 안에는 프로젝트 파일이 바로 들어 있습니다.

압축 해제로 생긴 바깥 폴더를 한 번 열어 위 내용이 보이는 곳까지 들어가세요.

2. GitHub의 기존 코드 폴더를 엽니다

기존 저장소에서 아래 두 폴더를 차례로 엽니다.

friends_card_room_no_betting → friends-card-room

기존 package.json이 보이는 화면이 맞는 위치입니다. 저장소 최상위가 아닙니다.

no_betting은 예전에 정한 폴더 이름일 뿐입니다. 이름을 바꾸거나 폴더를 새로 만들 필요가 없습니다.

3. 폴더 안에 파일을 덮어씁니다

GitHub에서 Add file → Upload files를 선택합니다. 1번에서 연 폴더의 내용 전체를 선택해 끌어넣습니다.

올리는 것: package.json, package-lock.json, server.mjs, lib, public, test 등.

올리면 안 되는 것: ZIP 파일 자체 또는 압축 해제로 생긴 바깥 폴더 하나. 바깥 폴더째 올리면 중첩 경로가 생깁니다.

변경 메시지는 Update card room to v2 등으로 입력하고 main에 커밋합니다. 제안/PR 방식으로 저장했다면 main으로 병합까지 해야 합니다. README·설명서·테스트도 이번 파일로 함께 바꿉니다.

동봉한 render.yaml은 새 프로젝트용 참고 설정입니다. 이번 업데이트 때문에 새 Blueprint나 새 서비스를 생성하지 않습니다.

재배포하면 현재 서버의 방·칩·게임 기록이 사라집니다. 진행 중이라면 핸드를 마치고 필요한 공개 결과를 저장한 다음 업데이트하세요.

5. 새 방에서 가상 칩 모드를 선택합니다

Render에서 Live가 되면 기존 사이트를 새로고침합니다. 홈페이지에 v2와 가상 칩 홀덤 · 베팅 + 폴드 선택지가 보이는지 확인합니다.

방 만들기 → 가상 칩 모드 선택 → 인원·초기 스택·SB·BB 설정 → 초대 → 승인 → 전원 준비 → 카드 나누기 순서입니다. 친구들은 기존처럼 초대 링크만 열면 됩니다.

기존 방은 업데이트 후 복원되지 않으므로 새 초대 링크를 보내 주세요. 재접속 실패 메시지가 뜨면 홈으로 돌아가 새 방을 만듭니다.

버전 확인은 사이트 주소 뒤 /healthz에서도 할 수 있습니다. "version":"2.0.0"이면 v2 서버입니다.

사용할 때 알아둘 것

폴드: 가상 칩 모드에서는 내 차례에 사용합니다. 이미 낸 칩은 팟에 남고, 폴드한 카드는 결과에서도 남에게 보이지 않습니다. 다음 핸드에는 다시 참가할 수 있습니다. 이미 올인했다면 추가 폴드는 없습니다. 베팅 없는 카드 비교 모드에서는 진행 중 언제든 폴드할 수 있습니다.

레이즈: 입력은 이번 단계의 총액입니다. 이미 20칩을 내고 총액 60을 입력하면 추가 40칩입니다.

자동 처리: D/SB/BB, 카드 배분, 베팅 차례, 사이드 팟, 족보, 동률·칩 정산을 서버가 처리합니다. 짧은 올인 후 레이즈 가능 여부도 검사합니다.

무료 재설정: 스택이 없어지면 핸드 종료 후 방장 관리의 전원 스택 무료 재설정을 사용합니다. 초기 스택 설정만 수정하는 것으로 현재 스택을 덮어쓰지 않습니다.

시간 초과: 가능한 경우 체크, 아니면 폴드하고 다음 핸드는 자리 비움입니다. 다음 핸드 자동 시작도 가상 칩 모드에서는 전원 준비 후에만 작동합니다.

가치 없는 게임 점수: 칩 구매, 현금 거래, 환전, 현금성 보상 기능이 없습니다.

처음에는 두 기기로 확인합니다

서로 다른 기기/브라우저에서 입장 → 승인 → 준비 → 한 핸드 진행 → 칩 정산을 확인합니다. 같은 브라우저 프로필의 일반 탭 두 개는 같은 자리로 연결됩니다.

로컬 자동 테스트 97개, 그 안의 시드 기반 무작위 1,000핸드 검사, 별도의 5장 조합 2,598,960개 분류 검사를 통과했습니다. 화면은 로컬 Chromium과 테스트용 API 연결로 확인했습니다. 사용자 Render의 실제 배포와 외부 기기 간 통신은 아직 검사하지 않았습니다.

메모리 저장 방식이므로 서버 재시작 시 방·칩·기록은 사라집니다. 결과 파일은 보관용이지 방 복원용이 아닙니다. 단일 서버 프로세스용입니다.

오류가 나면 먼저 확인할 위치

npm ci / lockfile 오류: Root Directory 아래에 이번 package.json과 package-lock.json이 나란히 있어야 합니다.

Cannot find module …holdem.mjs: 새 lib/ 폴더의 내용을 빠뜨리지 않았는지 확인합니다. lib/holdem.mjs도 올라가야 합니다.

화면이 아직 예전 버전: main에 반영됐는지, 그 커밋의 배포가 성공했는지, 파일을 기존 경로에 올렸는지 확인한 뒤 새로고침합니다.

방이 없다는 메시지: 재배포/재시작 후에는 새 방과 새 초대 링크가 필요합니다.
